# 0007 Payment screenshot storage

**Status:** accepted

## Decision

Payment screenshots are stored through a small interface, `storage.put(key, buffer)` and `storage.get(key)` (`apps/api/src/storage/local.js`). Today it writes to local disk under `UPLOADS_DIR` (default `./uploads`). Tests use an in-memory version. To move to cloud storage later (S3, Cloudflare R2), write one more file with the same two functions and pass it to `buildApp`. No route or service changes.

## Why

No schools have signed up yet, so local disk is enough and costs nothing. The interface keeps the move to the cloud cheap.

## Rules that do not change with the storage

- Only PNG, JPEG or WebP, checked by the file's real first bytes, not its name. At most 5 MB (the web app checks first, the API checks again; the route allows 8 MB of request so the API can answer 413 cleanly).
- A screenshot is served only to the head or to the parent who owns the invoice, with `Cache-Control: private, no-store` and `nosniff`. There is no public link.
- Keys are generated by the server, never taken from the client.
- The folder must be backed up with the database, and must be a persistent disk when hosted (a container's own disk is lost on redeploy).
- Screenshots are personal financial data under NDPA 2023. A lawyer should confirm how long they are kept.

## Gave up

Local disk does not work with several servers sharing one school. Moving to cloud storage fixes that.
